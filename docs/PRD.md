# AI EDA Copilot — 产品需求文档 (PRD)

> 版本：1.0
> 日期：2026-03-07
> 状态：草案

---

## 1. 产品概述

### 1.1 产品名称

**AI EDA Copilot**

### 1.2 产品形态

VS Code 扩展插件（Extension）

### 1.3 一句话描述

一款基于 AI 的电子设计助手，用户通过自然语言描述或上传固件代码，自动生成结构化的硬件设计报告，涵盖需求分析、BOM 清单、原理图意图、PCB 布局建议及嘉立创采购链接。

### 1.4 核心价值主张

- 将"想法"快速转化为可执行的硬件设计方案
- 大幅缩短元器件选型时间
- 降低原理图和 PCB 设计的入门门槛
- 通过 AI + 规则引擎双重校验，减少"DRC 通过但板子不能用"的情况
- 一键对接嘉立创商城，打通设计到采购的链路

## 2. 目标用户

### 2.1 用户画像

| 画像 | 描述 | 技术水平 |
|------|------|----------|
| 电子专业学生 | 课程设计、毕设、竞赛场景 | 入门～中级，了解基础电路但缺乏选型和布局经验 |
| 独立硬件开发者/创客 | Maker 项目、个人原型开发 | 中级，能画原理图但希望提高效率 |
| 小型硬件公司工程师 | 产品原型快速验证 | 中高级，追求效率和规范性 |

### 2.2 用户技术水平范围

- **新手**：不会画原理图和 PCB，需要 AI 从零引导
- **有经验者**：已具备设计能力，使用 AI EDA Copilot 提高效率、减少选型烦恼、获取设计建议

### 2.3 核心用户痛点

| 优先级 | 痛点 | 现有解决方式 |
|--------|------|-------------|
| P0 | 元器件选型耗时，不知道该用什么型号 | 手动查立创商城、翻 datasheet、问 ChatGPT |
| P0 | 原理图设计无从下手，不知道怎么连线 | 查 datasheet 典型应用电路、搜开源方案 |
| P0 | PCB 布局不规范，走线不合理 | 靠经验或反复试错 |
| P1 | DRC 通过但焊接后板子不工作（电源纹波、信号完整性、热设计等隐性问题） | 依赖人工 review 或踩坑后修板 |
| P1 | 在嘉立创找料号费时间，不确定有没有库存 | 手动在立创商城逐个搜索 |

## 3. 产品策略

### 3.1 V1 策略

**VS Code Extension-first**

- V1 作为 VS Code 扩展实现，复用 VS Code 的编辑器、资源管理器、Tab 和命令面板
- 不做独立 IDE
- 不做 Code-OSS 分叉
- 验证 AI EDA 工作流的可行性

### 3.2 V1 支持范围

**支持的项目类型：**

- ESP32 系列项目
- STM32 系列项目
- Arduino 生态开发板
- 常见传感器模块
- OLED / 小型显示模块
- 基础电源模块
- Wi-Fi / 蓝牙连接原型
- 简单控制板和验证板

**不支持（V1）：**

- FPGA 项目
- 射频/高频设计
- 高压电源设计
- 工业控制系统
- 可制造级别的 PCB 布线（Gerber 输出）

### 3.3 长期方向

- V2+：可制造级别 PCB 布线输出
- V2+：FPGA 支持
- V2+：独立桌面 IDE 可能性
- V2+：后端服务 + 用户账号体系
- V2+：付费订阅（免费版限制生成次数，付费版放开）

## 4. 商业模式

### 4.1 V1 阶段

- **免费使用**

## 5. 功能需求

### 5.1 输入方式

#### 5.1.1 自然语言输入

- 用户在侧边栏对话框中用自然语言描述项目需求
- 最低输入门槛：一句有意义的项目描述
- 示例："我想做一个基于 ESP32 的温湿度采集器，使用 DHT22 传感器，OLED 显示，电池供电"

#### 5.1.2 固件代码分析

- 用户选择当前 VS Code workspace 中的文件夹
- AI 解析固件代码中的 GPIO 使用、外设配置、第三方库引用
- 自动推导所需硬件并生成设计建议
- 支持的代码语言（V1）：C、C++、Python
- 当代码中存在未注释的模糊引用时，AI 应主动向用户提问确认

#### 5.1.3 快速模板

- 提供预设项目模板，加速需求填写
- V1 模板清单：
  - ESP32 传感器项目
  - STM32 控制板
  - OLED / 显示小板
  - 电池供电小板
  - 电源电路模块
- 模板预填核心需求字段，MCU 型号和外设可选填

#### 5.1.4 交互模式

- **默认展示对话框**（自然语言输入）
- 用户可切换到**表单模式**（结构化字段输入）
- 两种模式数据互通

### 5.2 AI 分析管线

#### 5.2.1 管线阶段

按顺序执行：

1. **RequirementSpec** — 需求分析与结构化
2. **BOMItem[]** — 元器件选型与 BOM 生成
3. **SchematicIntent** — 原理图意图表达
4. **PCBLayoutPlan** — PCB 布局规划
5. **Procurement** — 采购映射与嘉立创对接

#### 5.2.2 AI 补全策略

- **半自主补全**：AI 生成首版候选，用户审阅修改
- 所有 AI 推断内容必须标注来源：
  - `用户提供`
  - `AI 推断`
  - `待确认`
- 关键信息缺失时：暂停并向用户提问
- 非关键信息缺失时：生成临时方案并明确标注
- 需求过于模糊时：提供多个候选方向供用户选择

#### 5.2.3 AI 幻觉防护

- 每个 AI 输出强制标注**置信度**
- 所有报告包含**免责声明**
- 关键参数（电压、电流、封装、引脚定义）必须经过**规则引擎二次校验**
- 规则引擎参考标准：[嘉立创 EDA 设计规则](https://prodocs.lceda.cn/cn/pcb/design-design-rule/index.html)

### 5.3 设计审查（Design Review）

#### 5.3.1 审查引擎

采用 **AI 推理 + 规则库** 双引擎：

- AI 大模型：基于上下文的深度分析
- 规则引擎：基于嘉立创 EDA 设计规则和通用 PCB 设计规范

#### 5.3.2 审查覆盖范围

| 审查项 | 描述 |
|--------|------|
| 电源纹波 | 检查去耦电容配置、电源走线宽度、电源平面完整性 |
| 信号完整性 | 差分对等长、阻抗匹配、高速信号走线规范 |
| 热设计 | 大功率器件散热路径、铜皮面积、热过孔 |
| 封装匹配 | 封装与实际器件一致性、焊盘尺寸合理性 |
| 安全间距 | 参照嘉立创设计规则的间距要求 |
| 布局合理性 | 功能分区、去耦电容就近放置、天线净空区 |

### 5.4 输出报告

#### 5.4.1 报告位置

- 在新的 **Webview Tab** 中打开（类似 VS Code 内置的标签页）
- 侧边栏仅展示对话和快速摘要

#### 5.4.2 报告结构

按以下顺序组织：

1. **概览（Overview）**
   - 一句话项目摘要
   - 功能模块分解
   - 关键器件建议
   - 缺失信息 / 待确认项（必须存在此区块）
   - 项目就绪状态（必须存在此区块）
   - 风险提示
   - 下一步建议

2. **需求（Requirements）** — **受控可编辑区**
   - Requirements 是报告中唯一可直接编辑的区域
   - 编辑后需用户手动触发 Regenerate 重算下游模块
   - 优先展示：MCU/主控、电源、通信、显示、传感器
   - 折叠展示：成本范围、尺寸限制、产量意图、功耗目标、精度要求

3. **BOM 清单**
   - 默认表格视图，可展开行查看详情
   - 默认可见列：Designator、Comment、Footprint、Quantity、JLC Part Number
   - 展开详情：类别、制造商、MPN、替代件、置信度、确认状态
   - 替代件为一等公民，区分推荐首选和替代候选
   - 每个器件附带**立创商城精确详情页链接**

4. **原理图意图（Schematic Intent）**
   - 三种输出形式同时提供：
     - 文字描述（引脚级连接说明）
     - 模块级框图（Mermaid / SVG）
     - 引脚连接表
   - 网络分类：电源网络、通信网络、控制信号、模拟信号
   - V1 不生成最终原理图文件

5. **PCB 布局规划（PCB Layout Plan）**
   - 可视化功能分区块图
   - 元器件摆放建议
   - 板子尺寸和层数推荐
   - 文字布局建议（关键约束说明）
   - PCB 布线建议图（示意级别）
   - V1 不生成可制造级别布线/Gerber

6. **采购（Procurement）**
   - 嘉立创兼容性状态
   - 缺失封装/料号警告
   - 替代件建议
   - 一键跳转立创商城详情页链接
   - 贴片就绪度评估
   - V1 不提供自动下单功能

#### 5.4.3 报告交互

- 报告整体默认**只读**，但 **Requirements 区为受控可编辑区**（用户可直接修改需求字段）
- 修改需求后由用户手动点击 **Regenerate** 触发重新生成
- V1 支持**整份报告重新生成**，也支持**指定模块的局部重算**（如仅重算 BOM、仅重算 PCB 布局）
- 默认由用户手动触发 Regenerate，不自动重算
- **流式输出**：报告边生成边展示
- 完整报告生成时间目标：**3 分钟以内**

#### 5.4.4 免责声明

每份报告必须包含免责声明，明确说明：

- AI 生成的设计建议仅供参考
- 关键参数需用户自行验证
- 元器件库存和价格可能随时变化
- 不对因设计建议导致的损失承担责任

### 5.5 采购集成

#### 5.5.1 元器件库存校验

- 主要接口：**JLCPCB 官方 API**（[api.jlcpcb.com](https://api.jlcpcb.com/)）
- 备选接口：**jlcsearch API**（[docs.tscircuit.com](https://docs.tscircuit.com/web-apis/jlcsearch-api)）
- 实时查询库存、价格、规格数据
- 无对应料号时，AI 自动推荐替代件

#### 5.5.2 BOM 导出

- 格式：CSV，对齐嘉立创 SMT BOM 模板
- 必填字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| Comment | 是 | 器件型号/规格 |
| Designator | 是 | 位号 |
| Footprint | 是 | 封装 |
| Quantity | 是 | 数量 |
| 编号 | 有则填 | 立创商城元器件编号 |

- 导出的 CSV 可直接导入嘉立创 SMT 贴片下单页面

#### 5.5.3 其他导出

- 完整报告：Markdown
- 原理图意图：Markdown
- PCB 布局建议：Markdown
- 结构化数据：JSON
- 导出命名规则：`{项目名}_{时间戳}_{产物类型}.{扩展名}`

### 5.6 项目管理

#### 5.6.1 多项目支持

- 用户可同时管理多个独立项目
- 项目间数据完全隔离
- 每个项目一个独立文件夹

#### 5.6.2 多方案支持

- 同一项目下支持创建多个设计方案
- 提供**并排对比视图**：对比不同方案的 BOM 差异、成本差异、器件差异

#### 5.6.3 数据存储

- 存储位置：VS Code workspace 本地文件夹
- 存储路径：`.ai-eda/{项目名}/`
- 文件格式：JSON + Markdown
- 后续版本可加云端同步层

#### 5.6.4 报告版本管理

- 保留最近 **10 个版本**
- 用户可回看历史版本
- 用户可手动删除版本
- 用户可另存版本到本地任意路径
- 超出 10 个版本后自动淘汰最旧版本

#### 5.6.5 对话历史

- 用户与 AI 的对话历史保留
- 与报告版本关联存储

## 6. 交互设计

### 6.1 侧边栏（Side Panel）

- 插件激活后在 VS Code 侧边栏注册面板
- 默认展示**对话模式**
- 提供切换按钮切换到**表单模式**
- 快速操作按钮：
  - 分析项目
  - 生成 BOM
  - 生成 PCB 方案
  - 匹配嘉立创料号

### 6.2 Webview 报告页

- 点击"查看完整报告"后在新 Tab 中打开
- 报告内支持 Tab 切换各板块（概览/需求/BOM/原理图/PCB/采购）
- 流式输出，边生成边渲染
- 支持导出操作

### 6.3 异常处理

| 场景 | 处理方式 |
|------|----------|
| 网络断开 / API 超时 | 暂停生成，提示用户检查网络后重试 |
| 用户输入无意义内容 | AI 以普通对话方式回复（不触发报告生成） |
| 项目超出 V1 支持范围 | 回复"该功能暂时开发中" |
| AI 生成失败 | 显示错误信息，允许重试 |

## 7. 技术约束

### 7.1 核心技术栈

- TypeScript
- React（Webview UI）
- VS Code Extension API
- Claude API（AI 推理）
- JLCPCB API（库存校验）

### 7.2 AI 模型

- 主模型：Claude（通过用户自配 API Key 调用）
- API Key 存储：VS Code **SecretStorage API**（加密存储）

### 7.3 性能约束

| 指标 | 要求 |
|------|------|
| 完整报告生成时间 | ≤ 3 分钟 |
| 插件包大小 | ≤ 100 MB |
| 输出方式 | 流式输出（边生成边展示） |

### 7.4 兼容性

- VS Code 版本：跟随最新稳定版，无特殊最低版本要求
- 操作系统：Windows / macOS / Linux（VS Code 支持的平台）

### 7.5 国际化

- UI 语言：中文 + 英文双语
- 报告语言：用户可选中文或英文

### 7.6 数据隐私

- 用户项目数据完全本地存储
- 仅发送必要的分析请求到 AI API
- API Key 加密存储，不明文暴露
- V1 无后端服务，无数据上传

## 9. V1 不做的事情（明确排除）

| 排除项 | 原因 |
|--------|------|
| FPGA 项目支持 | 复杂度过高，V1 聚焦 MCU 类 |
| 可制造级 PCB 布线（Gerber 输出） | V2+ 规划，V1 仅做布线建议 |
| 最终原理图文件生成 | V2+ 规划，V1 输出原理图意图 |
| 自动下单 | V1 止步于采购指引和链接跳转 |
| 用户账号体系 | V1 无后端 |
| 付费订阅系统 | 等核心链路打通后引入 |
| 云端数据同步 | V1 纯本地 |
| 射频/高压/工业控制设计 | 超出 V1 目标用户范围 |

## 10. 成功标准

V1 阶段暂不设量化指标，以**功能完整度**为衡量标准：

- [ ] 自然语言输入 → 结构化报告 核心链路跑通
- [ ] 固件代码分析 → 硬件设计建议 链路跑通
- [ ] BOM CSV 导出可直接导入嘉立创 SMT 下单
- [ ] 立创商城精确料号链接可用
- [ ] 设计审查引擎能捕获常见设计缺陷
- [ ] 多项目、多方案管理可用
- [ ] 流式输出体验流畅

## 11. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| AI 推荐错误器件导致硬件损坏 | 高 | 置信度标注 + 规则引擎校验 + 免责声明 |
| 嘉立创 API 不稳定或变更 | 中 | jlcsearch 作为备选，本地缓存降级 |
| Claude API 调用成本过高 | 中 | 用户自备 Key，后续优化 prompt 降低 token 消耗 |
| 报告生成超时（>3 分钟） | 中 | 流式输出缓解等待焦虑，管线可分段生成 |
| 元器件库存实时变动 | 低 | 报告标注查询时间，提示库存可能变化 |

## 附录 A：嘉立创 BOM CSV 字段规范
